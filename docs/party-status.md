- 성공 200 `{success:true, state:<콘솔 상태>, remaining|topics:{…}}` · 값이 틀림 400 · 지금 할 수 없음 409 `{success:false, message}` · 화면이 낡음 409 `{…, stale:true}`

**화면 구현 규칙**
1. **409 를 받으면 상태를 다시 받는다.** `stale:true` 는 "조작이 적용되지 않았다"는 뜻이다(다른 창이 먼저 바꿨거나 같은 버튼을 두 번 보냄).
2. 버전은 "같은가 다른가"만 본다(크기 비교 금지). 스피드퀴즈 보드는 버전이 같아도 시간이 흐르면 `phase`·`remainingSeconds`·`word` 가 바뀐다 — 버전이 같다고 다시 그리기를 건너뛰지 않는다.
3. 스피드퀴즈 타이머는 서버의 `remainingSeconds` 로 그린다. 화면 시계로 0 을 계산해 `/finish` 를 보내지 않는다(서버가 자기 시계로 끝낸다). 본게임 타이머는 `timerElapsedSeconds`.
4. 단계는 `WAIT → READY → SHOW → REVEAL → WAIT`. READY 는 콘솔에만 있고 보드에는 `WAIT` 로 보인다. 콘솔은 READY 에서 `state.item`(영상 ID·시작초·사진 주소)으로 **띄우기 전에 재생·사진을 확인**하고, 안 되면 [다시 뽑기]. 띄운 뒤에 안 되면 `cancel`.
5. 정답·인정답안·보조·출처·난이도는 콘솔의 `card` 에만 있다. 보드 상태에는 정답 공개(`reveal`) 전까지 없다.
9. 오답 표시: `wrongTeam` 은 마지막 오답 팀, `bothWrong` 은 두 팀 모두 오답, **`freeChallenge` 는 두 팀 모두 오답이고 재생형(AUDIO)일 때만**(10-12 — 정지형은 plan §4-2 대로 [못 맞힘]) — 보드는 "○팀 기회" 대신 재생형이면 "자유 도전", 정지형이면 "양 팀 오답"을 그린다.
6. 응답이 JSON 이 아니거나 로그인 화면으로 넘어가면 "로그아웃됨"으로 표시한다(세션 만료·앱 재시작).
7. 조작 버튼은 응답이 올 때까지 잠근다. 스피드퀴즈 정답·패스는 서버가 0.3초 안의 두 번째를 409 로 거른다.
8. fetch 에는 `Accept: application/json` 을 붙인다(기존 공통 오류 처리가 이 헤더로 JSON/HTML 을 가른다).

## 구현하면서 정한 것 (plan 과 다르거나 plan 에 없던 것)
- `party_item`: `difficulty INT`, `use_yn VARCHAR(1)`, 날짜 `DATETIME(6)`, **유니크 키 (category, answer)**. 난이도 하/중/상 = 1/2/3.
- 제시 값은 AUDIO/IMAGE/TEXT 3종만 받는다(VIDEO 는 안 씀).
- 가져오기: URL 없는 AUDIO·파일명 없는 IMAGE 도 저장(출제에서만 제외). 대분류 + 정답이 같으면 덮어쓰되 **빈 칸은 기존 값을 지우지 않는다**(값을 비우는 것은 화면에서). `use_yn` 은 건드리지 않고, 영상이 바뀌면 재생 불가 표시를 푼다. 한 파일 안의 같은 대분류·정답은 두 번째 행 거부. `비고`·`추천자`·`제목스포` 는 저장 안 함. UTF-8 만 받는다.
- **사진 문제는 파일이 `party.image-dir` 폴더에 실제로 있어야 출제된다.** 파일명에 경로·윈도우 금지 글자가 있으면 거부(한글·공백은 됨).

## 행사 노트북 실행 — `scripts/party-start.bat` (10-10)
- **처음 한 번 파일 맨 위 세 줄을 고친다**: `PARTY_DIR`(사진·상태 파일 폴더, 공백 없는 절대 경로, 기본 `C:\party`) · `JAVA_HOME`(JDK 17) · `ALLOW_LAN`(기본 0).
- 더블클릭 → 폴더 쓰기 시험 → `dev,session-jdbc` 로 기동. 앱 로그는 창이 아니라 `PARTY_DIR\party-app.log`(직전 것은 `.prev.log`) — 창을 클릭하면 Windows 가 창 출력을 멈추고 그 사이 로그를 쓰는 요청이 전부 멈추기 때문. 1~2분 뒤 브라우저로 콘솔·보드. 창을 닫으면 앱이 꺼진다.
- **`ALLOW_LAN=0` 고정 — 휴대폰 예비 콘솔은 쓰지 않는다(10-12 결정, O-037 A).** 시드 계정(`a@a.com`·`test1~6`) 비밀번호가 공개 저장소의 코드에 있어서, `1` 로 열면 같은 와이파이의 누구나 관리자로 로그인해 정답을 보고 MC 를 로그아웃시킬 수 있다. 콘솔은 노트북 한 대, 소리도 콘솔 창("이 창")에서.
- **첫 실행은 인터넷이 될 때** — Maven 이 필요한 파일을 받아 둬야 오프라인에서도 뜬다(집 PC 에서 원격 저장소를 끊고 기동 확인, 10-10).
- 노트북 DB: **MariaDB 11**(10-12 결정), dev 설정의 `localhost:3306/song`(root, 비밀번호는 `application-dev.properties`)에 맞춰 만든다. 노래는 운영 `genre`·`song` 데이터만 덤프해 넣고, 파티 문제는 앱의 문제 관리에서 TSV 로 올린다 — 절차·운영 영향은 plan §2-3. **`schema.sql` 은 빈 DB 에서만 실행** — `DROP TABLE IF EXISTS` 가 31개라 문제·노래를 넣은 뒤 다시 돌리면 전부 지워진다.
- 배치 파일은 ASCII 로만 쓴다 — UTF-8 한글 + `chcp 65001` 이면 cmd 가 줄을 잘못 읽어 주석 일부를 명령으로 실행했다(10-10 실측).
- 로그는 UTF-8 — VS Code·메모장으로 연다. 이미 떠 있으면(8082 사용 중) 두 번째 실행은 로그를 건드리지 않고 멈춘다. 인자로 준 폴더는 상대 경로여도 절대 경로로 바꾼다(10-12).
- **재시작은 반드시 이 배치 파일로.** IDE·`mvnw` 로 직접 띄우면 dev 기본값(`../party-images`·메모리 세션)이라 다른 상태 파일을 읽어 새 게임처럼 보이고, 재시작마다 로그아웃된다(O-034 ⑬).
- **노트북 전원·업데이트(리허설 1 에서 설정 확인)**: 전원 연결 · 전원 옵션에서 "덮개를 닫으면" = 아무 것도 안 함, 화면 끄기·절전 = 안 함 · Windows 업데이트 일시 중지(밤은 활성 시간 밖이라 자리를 비우면 재부팅될 수 있다) · 행사 중 노트북에서 빌드·IDE 자동 빌드 금지(devtools 가 앱을 다시 띄운다).
- **소리**: 노트북 소리가 HDMI 로 TV 에 나가면 [미리 듣기]도 참가자에게 들린다 — 띄우기 전 미리 듣기는 이어폰을 꽂거나 하지 않는다. 플레이어 창은 노트북 화면에 **보이게** 둔다(최소화·완전히 가리면 크롬이 타이머를 늦춰 재생이 최대 1분 늦다) · TV 에는 띄우지 않는다(썸네일·제목). 인터넷이 끊긴 사이 콘솔·플레이어 창을 새로고침했다면 인터넷이 돌아온 뒤 그 창을 한 번 더 F5(유튜브 플레이어를 다시 받는다).
- 콘솔은 한 창만 — [문제 관리]는 새 탭으로 열리고, 문제 관리 화면에는 콘솔로 가는 링크가 없다(콘솔 두 개가 모두 "이 창" 재생이면 소리가 겹친다).
