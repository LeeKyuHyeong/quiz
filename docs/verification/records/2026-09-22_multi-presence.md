# 멀티 접속 상태(presence) — 창 전체를 닫아도 방에서 나가게 (O-018)
- 일자: 2026-09-22 (작업은 2026-09-21 밤 이어서)
- 유형: 기능 보강 (P0 — 멀티 핵심 동선: 유령 방장이면 아무도 시작 못 함)
- 브랜치: `main` 로컬 커밋 (푸시 전 — 개발자 확인 후 푸시 요청 예정)
- 판정: **조건부** — 자동 테스트·전체 회귀·로컬 실브라우저 5건 ✅. 운영(창 전체 닫기·휴대폰 앱 전환·배포 중 유지)은 배포 후 🙋
- 설계: `docs/multi-presence-design.md` (09-21 초안 → 이 기록 기준으로 갱신)

## 1. 배경
09-21 페이지 토큰(A'안) 운영 확인에서 **크롬 시크릿 창 전체를 닫으면 나가기 신호(`pagehide` → `sendBeacon`)가 서버에 오지 않아** 방장이 유령으로 남았다(탭 하나 닫기는 정상). 브라우저 강제 종료·절전·모바일 네트워크 끊김도 같다. 유령은 대기실에서 최대 24시간 자리를 차지하고, 방장이면 아무도 시작하지 못한다.

## 2. 결정 (개발자 2026-09-22)
설계 §6 권장안 5건을 확정하고, "권장안마다 놓칠 수 있는 부분을 공격해 **심각** 건이 없으면 그대로, 있으면 심각 건이 없어지는 방안으로 교체"하라는 지시. 권장안마다 커밋, 푸시는 5건 끝난 뒤 개발자 확인 후.

## 4. 구현 요약
- `RoomPresenceService`(신규): `SessionSubscribeEvent` 로 `"방:회원" → {세션}` 집합, `SessionDisconnectEvent` 로 제거(역방향 맵, 멱등). 비면 `game.multi.disconnect-grace-ms`(기본 60000) 뒤 나가기 예약, 재구독·페이지 GET·재참가가 취소. 종료 중(`ContextClosedEvent`) 끊김 무시. `onRestart` — 연결이 없는 참가자의 나가기를 다시 잡음.
- `RoomUnloadService`: 대기 목록에 예약 사유(탭 닫기 신호/연결 끊김) 추가. 끊김 예약은 기존 예약을 덮지 않음. `cancelDisconnectLeave`(폴링용). 실행 시 "아직 현재 예약인가"를 확인(대체된 예약이 새 예약을 지우지 않게).
- `WebSocketConfig`: 심플 브로커 하트비트 `{game.multi.ws-heartbeat-server-ms=10000, game.multi.ws-heartbeat-client-ms=30000}` + `messageBrokerTaskScheduler`.
- `MultiGameController`: 재시작 뒤 `onRestart`, 폴링 GET 에서 `cancelDisconnectLeave`.
- `multi-result.js`: 방장도 WS 연결, 방장은 RESTART 방송 무시.
- `GameRoomService.LEAVE_IGNORED_AFTER_RESTART`(5초) 상수화 — 동작 불변.

**테스트 설계상 주의:** 결과 화면 방장 테스트는 테스트 유예(300ms)가 재시작 직후 무시 구간(5초)보다 짧아 "방장이 남는다"만으로는 결함을 못 잡는다(운영 60초 > 5초에서만 드러남). 그래서 "재시작 뒤 방장 나가기 예약이 없다"(`isLeavePending`)로 확인한다.

## 8. checklist 점검
- 영향 범위: `RoomUnloadService` 호출처(컨트롤러 페이지 GET·재참가·`/unload`) 전부 확인, 기존 `MultiGameControllerUnload*Test` 회귀 통과. 설정은 코드 기본값(60000/10000/30000)이라 프로필 누락 없음, 테스트 프로필만 짧게 덮음.
- 상태·동시성: 예약 대체·취소·실행 경합은 `synchronized` claim 으로 "현재 예약만 실행". 같은 세션의 구독·끊김은 연결 처리 순서대로 옴(소스 확인), 끊김 이벤트 중복은 역방향 맵 제거로 멱등.
- 멀티플레이: 방장 퇴장·게임 중 방장 퇴장·새로고침·연결 끊김·재접속·강퇴 후 끊김·권한 없는 구독 — 자동 테스트 + 로컬 브라우저.
- 운영: **끊김으로 나간 것은 HTTP 요청이 없어 nginx 로그에 안 남고, 앱 로그도 debug 라 운영에서 보이지 않는다.** 운영 확인은 화면(60초 뒤 위임)으로 한다. INFO 로그 한 줄 추가는 별도 제안.
- nginx: 연결 유휴 끊김(`proxy_read_timeout` 기본 60초)은 서버 하트비트 10초로 트래픽이 있어 영향 없음(전에는 SockJS 25초 하트비트가 같은 역할).
