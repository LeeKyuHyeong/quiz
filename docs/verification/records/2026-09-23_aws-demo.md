## 2. 검증 — `prod,session-redis` 조합 (로컬, 에이전트 실행)
`spring.profiles.group.prod=session-jdbc` 때문에 `prod` 를 켜면 `session-jdbc` 가 따라온다. 여기에 `session-redis` 를 얹는 조합은
09-22 검증 범위 밖이었다(그때는 `dev,session-redis`·`dev,session-jdbc` 만). EC2 에서 처음 띄우기 전에 확인했다.

- 방법: 운영과 같은 이미지 `positivelee/quiz-app:latest` + 일회용 `mariadb:11.8`(schema.sql 31테이블 적재, `SPRING_SESSION` 두 테이블 포함) + `redis:7-alpine`, 전용 도커 네트워크

| 확인 | 결과 |
|---|---|
| 활성 프로파일 | `prod`·`session-jdbc`·`session-redis` **3개** (그룹 확장) |
| 기동 | ✅ 15초, `/actuator/health` `{"status":"UP"}` |
| 세션 쿠키 | ✅ `Set-Cookie: SESSION=…; HttpOnly; SameSite=Lax` |
| 세션 저장 위치 | ✅ **Redis** — `quiz:session:sessions:*`·`:expires:*`·`:expirations:*` |
| JDBC 저장소 | ✅ `SPRING_SESSION` **0행** (테이블이 있는데도 안 씀) |
| 재시작 유지 | ✅ 컨테이너 restart 후 같은 쿠키 → **새 `Set-Cookie` 0건**, CSRF 토큰 동일(`97d1f9c2…`) |

**판정: 조합 성립 ✅.** `session-jdbc` 가 같이 켜져도 `SessionAutoConfiguration` 이 Redis 를 먼저 잡고 JDBC 는 `@ConditionalOnMissingBean` 으로 물러난다.
EC2 에 `SPRING_PROFILES_GROUP_PROD` 같은 추가 환경변수는 필요 없다.

## 4. 기동 중 걸린 것 (2026-09-23 저녁)

### 4-1. RDS 가 TLS 를 강제 — JDBC 기본값과 충돌 ❌→✅
- 증상: 앱 컨테이너가 재시작 루프. `Error 3159 (08004): Connections using insecure transport are prohibited while --require_secure_transport=ON`
  → `entityManagerFactory` 생성 실패 → `Unable to determine Dialect without JDBC metadata`
- 원인: **RDS MariaDB 기본 파라미터 그룹이 `require_secure_transport=ON`.** MariaDB Connector/J 3.4.1 은 기본이 `sslMode=disable` 이라 거부당한다.
  VPS 는 같은 도커 네트워크 안(`jdbc:mariadb://db:3306`)이라 이 문제가 없었다 — 관리형 DB 와의 실제 차이.
- 조치: 파라미터 그룹을 바꿔 끄지 않고(재부팅 필요·암호화를 끌 이유 없음) **JDBC URL 에 `sslMode=trust` 추가**.
  전송 구간은 암호화되지만 **서버 인증서 검증은 하지 않는다**(검증까지 하려면 RDS CA 번들을 트러스트스토어에). 며칠 쓰고 지울 시연 환경이라 여기까지.
- 갈라서 확인한 것: `mariadb` CLI 는 기본 TLS 라 스키마 적재 성공(31테이블) · ElastiCache TLS 는 `redis-cli --tls … ping` → **PONG** → JDBC 한 곳만 문제로 좁힘

## 6. 2대 + ALB 세션 유지 시연 (2026-09-23 밤)
`http://quiz-alb-1927677700.ap-northeast-2.elb.amazonaws.com/` 에 `user@aws.demo` 로그인(에이전트 내장 브라우저, 개발자 크롬은 admin).
어느 인스턴스가 응답했는지는 ALB 액세스 로그 없이 알 수 없으므로, **양쪽을 번갈아 정지**해 한쪽만 살아 있는 상태를 각각 만들었다.
세션 동일성 지표는 세션에 매인 **CSRF 토큰**.

| 상태 | 인사말 | CSRF 토큰 | `/auth/validate-session` |
|---|---|---|---|
| 양쪽 healthy | AWS참가자 | `b182cfbe-99e0-45a7-af4d-9b7c2d1e4bd0` | `{"valid":true}` |
| **1번 정지**(2c 만 살아 있음) | AWS참가자 | **동일** | `{"valid":true}` |
| **2번 정지**(2a 만 살아 있음) | AWS참가자 | **동일** | `{"valid":true}` |

전체 새로고침(`navigate`)으로 확인했고 재로그인은 한 번도 없었다. → **같은 세션을 두 인스턴스가 번갈아 서비스했다 = 로그인 세션 외부화 성립 ✅**

### 시연 범위 한계 (의도된 것, 09-18 결정)
- **멀티 게임은 2대에서 동작하지 않는다.** presence·요청 제한·언로드 토큰은 그대로 인스턴스 메모리라 WS 브로드캐스트가 인스턴스를 넘지 못한다. 노래 시드도 없다.
- 시연은 **로그인 세션 유지 한 가지**로 좁힌다. 게임 플레이는 VPS(`game.kyuhyeong.com`, 1대)에서 보여준다.
