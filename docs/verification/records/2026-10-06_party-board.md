- 일자: 2026-10-06 (집 PC, 밤)
- 유형: 신규(화면)
- 우선순위: P1 (참가자가 보는 화면 · 정답 노출 금지가 핵심 — `party` 브랜치 · 로컬 전용)
- 판정: **조건부** — P1 AC ✅, 사진·GAME 힌트 화면·실제 TV 확장 디스플레이는 콘텐츠·장비가 있어야 해서 🙋(아래 9)

## 1. 요청과 목적
- 사용자가 원한 것: 콘솔에 이어 보드 화면.
- 개발자 확인 결과(10-06 밤 채팅 승인):
  - 설계는 목업 `#board` + plan §4-1. 관리자 사이드바 없는 전체 화면, `.game-page`(항상 다크), 글자는 `vw`/`vh`.
  - **목업과 다른 것 하나: 보드에는 YouTube 플레이어를 두지 않는다** — 노래 뮤직비디오가 정답을 보여 준다. 소리는 콘솔(또는 플레이어 창)이 낸다.
  - 연결 끊김·로그아웃은 참가자가 보는 화면이라 구석에 작게만.
- 진행 중 둔 가정:
  - 소리 문제에 "무엇을 말하면 정답"인지 한 줄을 보여 준다(SONG 제목 · ANIME 제목 · SOUND 프로그램·브랜드 · GAME 은 중분류가 "게임 맞히기"면 게임 이름, 아니면 캐릭터·유닛·맵). 출처는 README "MC 판정 규칙" — 바뀌면 콘솔 JS 의 규칙 상수와 함께 세 곳.
  - 힌트는 보드 상태에 열린 것만 실리므로 잠긴 힌트 수는 보여 주지 않는다.
  - 사진이 깨지면 보드에서는 사진만 숨긴다(경고는 콘솔 몫).

## 6. 수동 확인 시나리오
### 6-1. 실행함
시작 상태는 사용자가 21:50 에 직접 콘솔로 띄워 둔 노래 문제(남팀 오답)였다. 상태 파일을 복사해 두고 확인 뒤 앱을 멈춰 그대로 되돌렸다(재기동 후 보드가 같은 상태를 그림).
1. 보드가 기존 상태를 그림: "노래 · 2015~2019", 남팀 점수 흐림, "남팀 오답 → 여팀 기회", "노래 제목을 말하면 정답". ✅
2. 콘솔 [여팀 오답] → 보드 "양 팀 오답 — 자유 도전!"(강조), 흐림 해제, 꼬리 "자유 도전 — 먼저 맞히는 팀이 득점". 이때 보드 화면·보드 API 에 정답 없음. ✅
3. 콘솔 [남팀 정답] → 보드 정답 · "한동근 · 2016" · "남팀 +1"(팀 색), 꼬리 "다음 대분류는 MC 가". ✅
4. [다음] → QUIZ 뽑기(READY): 보드 "라운드 1 · 라운드 1 끝 · 다음 문제를 기다리는 중", 정답 없음. ✅
5. [보드에 띄우기] → "[과자] ㅎ ㄴ ㅂ ㅌ ㅊ" 큰 글씨(115px @1280), 정답 없음. ✅
6. [여팀 정답]·[+1] → [점수판] → VS 1:2 → [게임 종료] → "최종 결과 · 여팀 승리!" 여팀 강조, "수고하셨습니다!". ✅
